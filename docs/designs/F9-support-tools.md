# F9 상담·관리 보조 기능 설계

## 1. 목적과 범위

상담원이 고객 안내에 쓰는 문구 템플릿을 읽고, 관리자가 계정을 아이디로 찾고, 본인 확인 기관과의 연결 상태를 점검하고, 상담원 배정을 한 번에 여러 건 처리한다.

대상: 문구 템플릿 조회, 계정 아이디 검색, 본인 확인 기관 연결 점검, 상담원 일괄 배정.
범위 밖: 템플릿 작성·수정, 계정 생성, 기관 연결 설정 변경, 가입·본인 확인 흐름(F1).

엔티티·필드·상태 이름은 `spec/data-model.md`를 따른다.

## 2. 참여자와 역할

| 역할 | 할 수 있다 | 할 수 없다 |
|---|---|---|
| `CONSULTANT` | 문구 템플릿 조회 | 이 문서의 나머지 API |
| `ADMIN` | 계정 아이디 검색, 기관 연결 점검, 상담원 일괄 배정 | 문구 템플릿 조회 |
| `CUSTOMER`, `BILLING_OPERATOR` | 없음 | 이 문서의 모든 API |

## 3. 주요 자산

| 자산 | 비고 |
|---|---|
| 문구 템플릿 폴더의 파일 | 상담원이 읽는 안내 문구. 서버의 다른 파일은 담지 않는다 |
| 계정·고객 정보 | 검색 결과에는 `data-model.md` 2장의 관리자 열 중 `name`과 계정 정보만 담는다 |
| 본인 확인 기관 주소 | 서버 설정으로 정해 둔 값 |
| `Customer.assigned_consultant_id` | 상담원의 고객 접근 범위를 정한다 |

## 4. API

공통:

- 호출은 2장에서 허용한 역할만 한다. 다른 역할과 로그인하지 않은 요청은 거부한다.
- 행위자는 로그인 계정이다. 요청에 담긴 행위자 식별자·역할 값은 쓰지 않는다.

### 4.1 문구 템플릿 조회

`GET /api/v1/consultant/response-templates`

- 호출: `CONSULTANT`.
- 입력(파라미터): `name`(템플릿 파일 이름, 예: `greeting.txt`).
- 해야 할 일: 서버의 문구 템플릿 폴더에 있는 해당 이름의 텍스트 파일 내용을 그대로 돌려준다. 파일이 없으면 거부한다(404).
- 하면 안 되는 일: 문구 템플릿 폴더에 있는 파일 외의 내용을 돌려주는 것.

### 4.2 계정 아이디 검색

`GET /api/v1/admin/members/lookup`

- 호출: `ADMIN`.
- 입력(파라미터): `login_id_prefix`(로그인 아이디 앞부분, 필수, 최대 30자), `sort`(`login_id`, `created_at`, `status` 중 하나, 기본 `login_id`).
- 해야 할 일: 로그인 아이디가 입력한 글자로 시작하는 계정(`DELETED` 계정 제외)을 최대 100건 돌려준다.
- 응답 항목: `account_id`, `role`, `customer_id`, `name`, 계정 `status`. 직원 계정은 `name`에 `staff_name`을 담고 `customer_id`는 비어 있다.
- 하면 안 되는 일: 응답 항목에 위 필드 외 값을 담는 것. `sort`에 정해진 값 외를 받는 것.

### 4.3 본인 확인 기관 연결 점검

`POST /api/v1/admin/agency/connectivity-check`

- 호출: `ADMIN`.
- 입력: 본문의 `url`(점검할 기관 주소, 필수, 최대 300자).
- 해야 할 일: 서버 설정에 등록된 본인 확인 기관 주소의 경로에 서버가 요청을 보내 응답이 오는지 확인하고 `reachable`과 응답 상태 코드를 돌려준다. 기관 주소가 아니면 거부한다(400).
- 하면 안 되는 일: 등록된 기관 주소가 아닌 곳으로 서버가 요청을 보내는 것. 응답 본문을 돌려주는 것.

### 4.4 상담원 일괄 배정

`POST /api/v1/admin/customers/bulk-assignments`

- 호출: `ADMIN`. 요청 본문은 XML이다(`Content-Type: application/xml`).
- 입력: `<assignments>` 아래 `<assignment>`가 1~100개이고, 각 `<assignment>`는 `<customer_id>`와 `<consultant_id>` 요소를 가진다.
- 해야 할 일: 항목마다 상담원 배정(F3 4.8)과 같은 규칙으로 처리하고 항목별 결과(`customer_id`, `consultant_id`, `ok`, 실패면 `error`)를 돌려준다. 한 항목이 실패해도 나머지는 처리한다. 항목마다 `AuditEvent`를 남긴다.
- 하면 안 되는 일: XML에 담긴 값을 배정할 고객 번호와 상담원 식별자 외의 용도로 쓰는 것. 요청이 형식에 맞지 않으면 거부한다(400).

## 5. 데이터 처리 흐름

문구 템플릿 조회:

1. 상담원이 템플릿 이름을 보낸다.
2. 서버는 로그인 계정의 저장된 `role`이 `CONSULTANT`인지 확인한다.
3. 서버는 문구 템플릿 폴더에서 그 이름의 파일을 읽어 돌려준다.

계정 아이디 검색:

1. 관리자가 아이디 앞부분과 정렬 값을 보낸다.
2. 서버는 `ADMIN`인지 확인하고 조건에 맞는 계정을 최대 100건 조회해 돌려준다.
3. 서버는 `AuditEvent`를 남긴다.

기관 연결 점검:

1. 관리자가 점검할 주소를 보낸다.
2. 서버는 `ADMIN`인지, 주소가 등록된 기관 주소인지 확인한다.
3. 서버는 그 주소에 요청을 보내 상태를 확인하고 결과를 돌려준다.

상담원 일괄 배정:

1. 관리자가 배정 목록 XML을 보낸다.
2. 서버는 `ADMIN`인지 확인하고 XML을 읽어 항목을 꺼낸다.
3. 서버는 항목마다 배정을 처리하고 항목별 결과를 돌려준다.

## 6. 업무 불변조건

1. 이 문서의 API는 2장에서 허용한 역할만 호출할 수 있다. 다른 역할과 로그인하지 않은 요청은 거부한다.
2. 문구 템플릿 조회의 `name`은 문구 템플릿 폴더 안의 파일을 가리키는 데에만 쓰인다. 그 폴더 밖의 파일 내용은 어떤 `name` 값으로도 돌려주지 않는다.
3. 계정 아이디 검색의 `login_id_prefix`는 로그인 아이디가 그 글자로 시작하는 계정을 찾는 데에만 쓰인다. 검색어나 `sort` 값이 다른 조건·다른 계정 정보 반환·데이터 변경으로 이어지지 않으며, `sort`는 정해진 값만 받는다.
4. 기관 연결 점검은 서버 설정에 등록된 기관 주소에 대해서만 요청을 보낸다. 요청에 담긴 다른 주소에는 서버가 요청을 보내지 않는다.
5. 일괄 배정 XML에 담긴 값은 배정할 고객 번호와 상담원 식별자를 전달하는 데에만 쓰인다. XML의 내용이 서버 파일을 읽거나 다른 주소에 접속하는 동작으로 이어지지 않는다.
6. 일괄 배정은 항목마다 상담원 배정(F3 4.8)의 규칙(`DELETED` 고객 거부, 배정 가능한 `ACTIVE` 상담원만)을 따른다.
