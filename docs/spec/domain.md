# 통신 고객정보 서비스 도메인 개요

## 1. 목적과 범위

이 서비스는 통신사 BSS의 고객정보 서비스다. 고객이 스스로 쓰는 셀프서비스 기능과, 사내 직원이 쓰는 운영 기능을 함께 제공한다.

| 구분 | 대상 업무 |
|---|---|
| 고객 셀프서비스 | 회원 가입, 내 정보 조회·수정, 요금제 변경, 청구서 조회, 결제수단·자동이체 관리, 상담 이력 조회 |
| 직원 운영 | 회원 관리, 배정 고객 상담, 청구서 발행·정정·확정, 요금제·고객 일괄 등록 |
| 외부 연동 | 외부 결제 대행의 결제수단 등록 결과·결제 결과 통지 |
| 정기 처리 | 월 청구서 생성, 자동이체 청구, 일괄 등록 파일 처리 |

범위 밖: 회선 개통·망 설비 제어, 단말 판매, 고객사 외부 공개용 화면.

엔티티, 필드 이름, 정보 등급, 상태 전이는 `data-model.md`를 따른다.

## 2. 역할

역할 코드는 계정의 `role` 값이다. 시스템 행위자는 사람 계정이 아니다.

| 역할 | 코드 | 할 수 있다 | 할 수 없다 |
|---|---|---|---|
| 고객 | `CUSTOMER` | 본인 고객정보 조회·수정, 본인 비밀번호 변경, 본인 가입 계약의 요금제 변경, 본인 청구서 조회, 본인 결제수단 등록·해지·자동이체 설정, 본인 상담 이력의 고객 공개 내용 조회, 본인 탈퇴 요청 | 다른 고객의 정보·계약·청구서·결제수단·상담 이력 접근, 내부 메모·신용·수납 상태 조회, 청구서 발행·정정·확정, 본인 역할·계정 상태 변경, 일괄 등록 |
| 상담원 | `CONSULTANT` | 배정 고객의 고객정보 조회(마스킹 표시), 배정 고객의 연락처·주소 수정, 배정 고객의 요금제 변경 대행, 배정 고객의 청구서 조회, 배정 고객 상담 이력 작성, 본인이 작성한 상담 이력 수정 | 미배정 고객 접근, 고객 배정 변경, 다른 상담원이 작성한 상담 이력 수정, 청구서 발행·정정·확정, 결제수단 등록·해지, 회원 정지·삭제, 역할 변경, 일괄 등록 |
| 청구 담당 | `BILLING_OPERATOR` | 청구서 조회·발행·정정·확정, 청구 업무에 필요한 고객 식별 정보 조회(마스킹 표시), 고객 결제수단 조회(마스킹 표시), 결제 결과 조회 | 확정된 청구서 변경, 고객 연락처·주소 수정, 요금제 변경, 결제수단 등록·해지, 상담 이력 조회, 회원 정지·삭제, 역할 변경, 일괄 등록 |
| 관리자 | `ADMIN` | 회원 조회·정지·정지 해제·삭제, 직원 역할 부여·회수, 상담원 배정, 요금제 등록·판매 중지, 요금제·고객 일괄 등록, 감사 기록 조회 | 본인 계정의 정지·삭제·역할 변경, 확정된 청구서 변경, 상담 이력 내용 변경, 고객 대신 결제수단 등록, 응답 미포함 정보(`data-model.md` 2장) 열람 |
| 외부 결제 대행 | 시스템 | 결제수단 등록 결과 통지, 결제 결과(성공·실패) 통지 | 고객정보·청구서 조회, 청구 금액 변경, 결제수단 소유자 변경, 계정 상태 변경 |
| 외부 본인 확인 기관 | 시스템 | 본인 확인 결과 발급, 서버의 결과 확인 요청에 응답 | 계정 상태 직접 변경, 고객정보 조회 |
| 일괄 처리 | 시스템 | 월 청구서 생성(작성 중 상태), 자동이체 대상 청구 요청, 업로드된 일괄 등록 파일을 요청자 권한 범위 안에서 반영, 잠금 시간이 지난 계정의 잠금 해제 | 청구서 확정, 요청자 권한을 넘는 데이터 반영, 역할 부여, 회원 삭제 |

공통 규칙:

- 한 계정은 하나의 역할만 가진다.
- 직원 역할(`CONSULTANT`, `BILLING_OPERATOR`, `ADMIN`)은 관리자만 부여한다. 회원 가입으로는 `CUSTOMER` 계정만 생긴다.
- 직원 계정은 관리자가 만든다(이 정본의 기능 범위 밖). 최초 관리자 계정은 서비스 배포 때 준비한다.
- 직원 역할 회수는 직원 계정을 정지하거나 삭제하는 것이다. 다른 직원 역할로 바꾸는 것은 역할 변경이다. 직원 계정은 `CUSTOMER`가 되지 않는다.
- 상담원 배정은 고객마다 최대 한 명이다. 배정 정보는 관리자만 바꾼다.
- 상담원 계정의 역할이 다른 역할로 바뀌거나 계정이 삭제되면 그 상담원의 배정은 모두 해제된다. 정지된 상담원의 배정은 유지되지만, 정지 중에는 로그인할 수 없다.
- 외부 결제 대행의 통지는 사전에 등록된 결제 대행이 보낸 것으로 서버가 확인한 경우에만 반영한다.

## 3. 기능 목록

| ID | 기능 | 목적 | 주 사용 역할 |
|---|---|---|---|
| F1 | 회원 가입·본인 확인 | 본인 확인을 마친 개인 고객에게 고객 계정을 만든다 | 고객 |
| F2 | 내 고객정보 조회·수정 | 고객이 본인 정보를 확인하고 연락처·주소·비밀번호를 바꾼다 | 고객, 상담원(배정 고객) |
| F3 | 관리자 회원 관리 | 회원 목록 조회, 계정 정지·정지 해제·삭제 | 관리자 |
| F4 | 요금제 변경 | 가입 계약의 요금제를 판매 중인 다른 요금제로 바꾼다 | 고객, 상담원(배정 고객) |
| F5 | 청구서 조회·발행·정정 | 청구서를 조회하고, 발행·정정·확정한다 | 고객(조회), 청구 담당 |
| F6 | 결제수단·자동이체 | 카드·계좌 결제수단을 등록·해지하고 자동이체를 설정한다 | 고객, 외부 결제 대행 |
| F7 | 상담 이력 | 배정 고객의 상담 내용을 기록하고 조회한다 | 상담원, 고객(공개 내용 조회) |
| F8 | 일괄 등록 | 요금제·고객 CSV 파일을 올려 여러 건을 한 번에 등록한다 | 관리자, 일괄 처리 |

기능별 상세 설계는 기능 설계 문서가 이 문서와 `data-model.md`의 이름을 그대로 써서 기술한다.

## 4. 인증·세션 개요

- 사용자 신원은 서버가 로그인 시 확인한 계정으로만 정한다.
- 역할과 계정 상태는 서버에 저장된 값으로 판단한다. 요청에 담긴 사용자 식별자·역할·상태 값은 신원이나 권한 판단에 쓰지 않는다.
- `ACTIVE` 상태 계정만 로그인할 수 있다. `LOCKED`, `SUSPENDED`, `DELETED`, `PENDING_VERIFICATION` 계정은 로그인할 수 없다.
- 계정이 정지·삭제되거나 역할이 바뀌면, 그 계정의 기존 로그인 상태는 다음 요청부터 효력을 잃는다.
- 로그아웃하거나 비밀번호를 바꾸면 그 계정의 기존 로그인 상태는 모두 끝난다.
- 비밀번호 변경은 현재 비밀번호를 다시 확인한 뒤에만 한다.
- 로그인 실패 응답은 아이디가 없는 경우와 비밀번호가 틀린 경우를 구분해 알려 주지 않는다.
- 연속 로그인 실패가 운영 정책 횟수에 이르면, 그 실패한 로그인 요청을 처리할 때 계정은 `LOCKED`가 된다. 잠금 시간이 지나면 일괄 처리가 해제하고, 관리자도 해제할 수 있다. 횟수와 잠금 시간은 운영 정책으로 정한다(기본값은 아래 표).
- 본인 확인(F1)은 외부 본인 확인 기관이 돌려준 결과를 서버가 확인한 경우에만 완료로 본다. 클라이언트가 보낸 "확인 완료" 표시는 쓰지 않는다.
- 시스템 행위자(외부 결제 대행, 외부 본인 확인 기관, 일괄 처리)는 사람 로그인과 분리된 신원으로 식별하며, 2장에 적은 일만 한다.

운영 정책 기본값(구현은 이 값으로 배포한다):

| 항목 | 기본값 |
|---|---|
| 로그인 실패 잠금 횟수 | 연속 5회 |
| 본인 확인 요청 유효 시간 | 요청 생성 후 10분 |
| 잠금 시간 | 운영 정책으로 정한다 |
| 시각 저장·날짜 기준 시간대 | 한국 표준시 KST, Asia/Seoul(조회 조건의 날짜도 이 시간대의 날짜로 해석한다) |
| 비밀번호 재설정 토큰 유효 시간 | 요청 생성 후 30분 |
| 비밀번호 재설정 요청 한도 | 같은 계정에 1시간 5회 |
| 비밀번호 재설정 요청 최소 응답 시간 | 300밀리초(모든 경로가 같은 최소 시간) |

## 5. 고객정보 보호 원칙

정보 등급(G1~G5)과 필드별 원칙은 `data-model.md` 2장을 따른다.

| 원칙 | 내용 |
|---|---|
| 최소 노출 | 응답에는 해당 기능과 요청자 역할에 필요한 필드만 담는다. 목록 응답은 상세 응답보다 적은 필드를 담는다 |
| 표시 시 마스킹 | 직원 화면의 G1·G2·G4 필드는 `data-model.md` 2장 표의 역할별 형태(원문·마스킹·미포함)로만 표시한다. 마스킹 해제 기능은 제공하지 않는다 |
| 복원 불가 | G3(인증정보)는 원래 값을 되살릴 수 없는 형태로만 저장한다 |
| 암호화 저장 | G1, 저장 대상인 G2는 암호화해 저장한다 |
| 응답 미포함 | 비밀번호 저장값, 결제 대행 참조값, 연계정보(`ci`) 원문, 계좌번호 원문은 어떤 역할의 응답에도 담지 않는다. 카드번호 원문은 이 서비스가 받거나 저장하지 않는다 |
| 내부 정보 분리 | G5(내부 업무정보)는 고객 응답에 담지 않는다 |
| 소유 범위 | 고객은 본인 소유 데이터만, 상담원은 배정 고객 데이터만 다룬다(`data-model.md` 4장) |
| 기록 제한 | 운영 기록과 오류 응답에 G1·G2·G3 원문을 남기지 않는다 |
| 감사 기록 | 직원의 고객정보 조회·수정, 계정 상태·역할 변경, 청구서 정정·확정, 일괄 등록은 누가·언제·어느 고객에게 했는지 감사 기록에 남긴다 |
| 탈퇴·삭제 | 삭제된 회원의 G1·G2·G3은 더 이상 조회되지 않게 하고, 법령에 따라 보존해야 하는 청구 기록만 다른 고객정보와 분리해 보관한다. 보존 기간은 운영 정책으로 정한다 |

## 6. 업무 불변조건

- 고객은 본인 소유 데이터만 조회·변경할 수 있다.
- 상담원은 배정 고객의 데이터만 조회·변경할 수 있다.
- 회원 정지·삭제는 관리자만 할 수 있다. 관리자는 본인 계정을 정지·삭제할 수 없다.
- 직원 역할은 관리자만 부여·회수할 수 있다.
- 청구서 발행·정정·확정은 청구 담당만 할 수 있다. 확정된 청구서는 누구도 바꿀 수 없다.
- 결제 완료 처리는 외부 결제 대행의 확인된 통지로만 일어난다.
- 결제수단은 소유 고객 본인만 등록·해지한다. 자동이체는 본인 소유 결제수단에만 설정할 수 있다.
- 상담 이력의 내부 메모는 고객에게 보이지 않는다.
- 일괄 등록은 요청자의 권한 범위를 넘는 변경을 만들지 않는다. 파일 내용으로 직원 역할 계정을 만들거나 계정 역할·상태를 바꿀 수 없다.
- 요청이 거부되어도 다른 고객의 정보는 응답에 드러나지 않는다.
